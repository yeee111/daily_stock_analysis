## 二、B1 定案：默认全关 + 灰度触发键白名单（接入硬前提）

**本节是接入的硬前提，不是建议。**

1. **模块默认全关**：`RiskConfig()` 与 `RiskConfig.from_profile(None/空配置)` 均为七项全关。生产策略档 id=1 当前 `{"entry":{},"exit":{},"risk":{}}` 全空 → 接入后**账户 1/2 默认零行为变化**（主板口径，见 §八 S5 边界）。任务书默认参数（P0 5% / RR 1.5 / 预算 0.2×10 / 最小单 5000）由干跑脚本/示例配置**显式传开关**启用，不再是模块默认。
2. **触发键白名单**（仅下列**新增风控键**能启用对应规则；数值触发键须为有限正数，NaN/Infinity 视同未配置）：

| 规则 | 触发键（显式配置才启用） | 仅参数键（**不触发**启用） |
|---|---|---|
| P0 兜底 | `exit.fallback_stop_loss_pct`（别名 `fallback_stop_pct`）、`risk.fallback_stop_enabled` | — |
| RR 过滤 | `entry.min_rr`（别名 `min_reward_risk`）、`risk.rr_filter_enabled` | `entry.rr_max_stop_width` |
| 出场冷却 | `risk.stop_cooldown_scope`（必须显式给 off/stop_only/all） | `risk.stop_cooldown_days`（只配天数不启用，避免范围歧义） |
| 现金预算 | `risk.cash_reserve_pct`、`risk.budget_enabled` | `entry.max_weight`、`entry.max_names`（**既有语义键，绝不触发风控**） |
| 最小单金额 | `entry.min_order_amount`、`risk.min_amount_enabled` | — |
| 坏目标 | `risk.bad_target_enabled`（止盈缺失或 ≤ 拟成交价即拦） | — |
| 止盈空间 | `entry.min_target_space`、`risk.target_space_enabled` | — |

3. 显式 `*_enabled` 布尔键优先：`true` 可单独启用（参数走默认），`false` 一票否决；`risk.cooldown_enabled:false` 强制冷却 off。
4. 用户只调 `entry.max_names/max_weight`（持仓数/权重）不会意外启用任何风控——杜绝审查指出的"行为劫持"。
5. **回滚①（配置回滚，绑定本灰度口径）**：从策略档**删除全部触发键**（或全部 `*_enabled:false` + `stop_cooldown_scope:"off"`）→ `from_profile` 回到全关实例 → 行为立即回到原策略，**无需改代码**。因模块默认即全关，"删键即回原策略"在结构上成立，不依赖任何接入层约定。

## 八、不修项与已知边界（写明理由）

1. **S5 北交所/科创板分支（不修）**：模块 `clamp_buy_qty` 对 bse 按整百取整（上游 L327-328 是 ≥100 放行不取整），且闸门对 `intended_qty` 二次 clamp 会把科创板零股加仓（上游 L3003 不再 clamp）归零——**全关实例在 star/bse 板块下不是严格零行为变化**。不修理由：现网 `.env PAPER_TRADING_ALLOWED_BOARDS=main`（审查实测确认），star/bse 被上游 L2961 板块过滤挡在闸门前，无实际影响；本轮保持改动聚焦。**适用边界声明：本文"零行为变化"承诺仅限主板口径；未来放开 star/bse 前必须先对齐上游整手语义（bse 分支 + 去掉二次 clamp），否则返工。**
2. **S1 价格推断局限（模块已改优先级，干跑保留回退）**：干跑窗口 11 笔卖出无跳空/滑点，推断全部吻合；含跳空的窗口干跑 stop_only 结果不可信。正式接入按 §五第 10 项由引擎动作标记，`stop_only` 批准以此为前提。
3. **T1 干跑简化假设残留**：兜底止损已按 `min(开盘, 止损)` 建模；其余卖出按原流水实际价重演（不受影响）。原"精确成交假设与原引擎一致"的不准确表述已修正。
4. **T4 预算浮点口径**：可买量用 float（上游 Decimal），极端边界可能少算 1 股进而少 1 手；方向只缩不放，资金安全无虞，非必改。
5. **口径限制**：干跑是信号流反事实演算（释放现金不买流水外新信号 → 权益差为下界估计；carried 启发式仅展示）。**T3：拦截清单/冷却边际的"原结局估算"为价差口径，不含期末浮盈与 FIFO 分批成本，与真实权益边际方向可能相反**（实例：RR1.0+全冷却逐笔估算省钱 299.89 元，真实权益边际 -4.92 元）——逐笔估算仅供归因，方案优劣以逐日权益曲线为准。不能替代 fork 账户真实引擎 A/B（任务书已安排测试角色）。
6. **行业集中度、止损滑点建模**：任务书低优先仅设计，未实现。
7. **参数决策留给用户**：RR 阈值 1.0 vs 1.5、冷却 all 去留——边际数据已披露，模块全可配，不构成接入障碍。
