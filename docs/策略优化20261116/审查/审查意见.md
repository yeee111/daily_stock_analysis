## 三、阻断级问题（1 个）

### B1. 灰度口径未定案：按当前接入说明直接实施，默认配置即改变账户 1/2 行为

- **位置**：`实现/接入说明.md` §五"配置注入与灰度"（L149-157）、§六回滚①（L167）；`实现/纸面风控模块.py` L107-126（RiskConfig 默认值）。
- **触发场景**：接入层按说明建议 `risk_cfg = rc.RiskConfig.from_profile(policy.config)` 每次 run 解析。当前生产策略档 id=1 `config_json={"entry":{},"exit":{},"risk":{}}` 全空（调研证实），`from_profile({})` 返回**默认全开**实例（RR1.5 + P0 + P2 开，仅冷却 off）。账户 1（对照）与账户 2 同时启用风控。
- **问题与依据**：干跑实测全开方案期末权益 **-1,820.33 元、拦截 13 笔买入**（干跑_风控对比_结果.md L13/L22）——这不是零行为变化，而是直接改写两个生产账户的策略。违反审查基准"默认配置下必须零行为变化"与任务书硬约束 1（接入前列明影响范围等用户批准）。接入说明自己已标注"待确认"，但：
  1. 灰度口径（"显式出现任一风控键才启用"）**只是建议，未定案**，且**触发键清单未定义**——`entry.max_names` / `entry.max_weight` 是**既有语义键**（控制持仓数/权重，调研 §一.2），若被算作"任一风控键"，用户只想调持仓数就会意外启用 RR1.5+P0+P2 全部默认风控，属隐蔽的行为劫持。

- **最小修复**（改文档即可，不动模块）：接入说明把灰度口径从"建议"升为**接入前置条件**，并显式列出触发键白名单 = 仅**新键**（`exit.fallback_stop_loss_pct`、`entry.min_rr`、`entry.rr_max_stop_width`、`entry.min_order_amount`、`risk.stop_cooldown_scope`、`risk.stop_cooldown_days`、`risk.cash_reserve_pct`）及五个 `*_enabled` 开关；明确 `entry.max_names/max_weight` **不触发**灰度（只作为已启用风控的参数）。回滚①的表述绑定灰度口径。完成后本条即关闭。

## 四、建议级问题（7 个，按影响排序）

### S1. exit_kind 价格贴合推断会漏掉跳空/滑点止损出场 → `stop_only` 冷却静默失效

- **位置**：`实现/纸面风控模块.py` L326-336（`infer_exit_kind`，容差 0.005）；`实现/接入说明.md` §五接入点 2（L144"第一期用 infer_exit_kind 推断"）；上游 `paper_trading_service.py` **L2881-2884**。
- **触发场景**：持仓跳空低开穿越止损（开盘 < stop）。真实引擎成交价 = `min(open_price, stop)` = **开盘价**（L2882，注释明确 "a gap through it fills at the open"），与 stop 价差远超半分容差 → 推断返回 `None`（实测：`infer_exit_kind(47.0, 47.3, 50.0) → None`）→ `stop_only` 冷却不计数，跳空止损（恰是最该冷却的出场）次日即可回补。止盈跳空同理（`max(open, target)`）。`risk.slippage_bps>0` 时**所有**止损/止盈出场都推断失败。
- **依据与反例排除**：本窗口 11 笔卖出全部精确贴合（只读库抽查 600028 11-05 开 5.55>stop5.52、600276 11-12 开 47.9>stop47.3 等，均无跳空），所以"干跑验证全部吻合"属实——但这是样本巧合，不是结构保证。`all` 范围不受影响（任何卖出都计数），且冷却默认 off、干跑结论推荐开 all，故降为建议；**若用户批准开 `stop_only`，本条升级为阻断**。
- **最小修复**：正式接入时不用价格推断——引擎在 L2882/2884 已知 `trigger`，且卖出 `plan_item` 的 `action` 字段就是 `stop_loss/take_profit`（L2942）。最小改法是 `_order_note`（L3266-3268）对 exit 单追加动作标记（如 `paper trading: signal #142 [stop_loss]`，一行改动，`signal #(\d+)` 正则解析不受影响，零 schema 改动），接入说明"二期改 note 改动面更大暂不建议"的判断与实际代码不符，应重新评估。在此之前，文档应明示 `stop_only` 对跳空/滑点出场不可靠。

### S2. 接入点 1 不会把 fallback 透传到止损体检——与接入说明声明矛盾

- **位置**：`实现/接入说明.md` §五接入点 1（L115"source='fallback' 自然透传到体检/看板"）；上游 `paper_trading_service.py` **L2314**（`_position_stop_health` 直接调 `_effective_exit_levels`，不经过 `_exit_levels`）。
- **触发场景**：按 diff 只在 `_exit_levels`（L2248 后）插兜底。裸仓 600760 获得兜底止损并能出场（计划链路 ✅），但止损体检走的是 L2314 的独立调用，`exit_config` 里新增的 `fallback_stop_loss_pct` 键被 `_effective_exit_levels` 无视 → 体检**继续报"无止损保护仓位"**（L2319-2327），看板/告警与实际保护状态矛盾，用户会误判兜底未生效。
- **依据**：`_exit_levels` 全仓仅 L2672 一个调用点（grep 证实）；体检 L2289-2318 自建 latest_buy + signal 视图，与计划链路平行。
- **最小修复**：体检在 L2314 之后做同样的"stop is None 才补"判断（约 +3 行），或把兜底下沉为 `_effective_exit_levels` 的独立第三优先级分支（读新键、不动 `stop_loss_pct` 语义，两条链路一次覆盖，改动更收敛）。二选一，并同步修正接入说明的透传声明与行数估计。

### S3. `from_profile` 遇 NaN/Infinity 配置直接崩溃（实测复现）

- **位置**：`实现/纸面风控模块.py` L177（`int(num(risk,"stop_cooldown_days",...))`）、L190（`int(num(entry,"max_names",...))`）。
- **触发场景**：策略档 JSON 含 `NaN`/`Infinity` 字面量（Python `json.loads` 默认接受；`float("1e999")` 也产生 inf）。实测：`{"risk":{"stop_cooldown_days": NaN}}` → `ValueError: cannot convert float NaN to integer`；`{"entry":{"max_names": Infinity}}` → `OverflowError`。正式接入后这会让**整个每日纸面 run 抛异常中断**，而上游同类非法值全部优雅降级（`_coerce_pct` L543-558 降 None 并告警），健壮性口径不一致。另 NaN 流入 `cash_reserve_pct`（L191）会经 `min/max` 传播为 NaN → `max(0.0, cash-nan)=0.0` → 预算恒 0 拦掉所有买入（静默）。
- **最小修复**：`num()` 内加 `math.isfinite` 检查，非有限值回退默认并（由调用方）告警；一行防御覆盖全部键。

### S4. 冷却对交易日历缺口 fail-open，静默放行（实测复现）

- **位置**：`实现/纸面风控模块.py` L306-307（`today not in day_index → return 0`）、L314-315（出场日不在日历 → 跳过该笔）；`实现/接入说明.md` §五（L145"取窗口日历转 ISO 字符串即可"，窗口长度未约定）。
- **触发场景**：① 接入方传入的 `trading_days` 窗口太短，未覆盖 5 个交易日前的出场日 → 该出场被忽略，冷却失效；② `get_trading_dates` 失败/返回空（上游 L477-481 该函数可返回 None）→ 日历空 → 冷却整体静默关闭。实测：日历 `['2026-11-06','2026-11-09']` 含今日但缺出场日 11-05 → 返回 0；日历缺今日 → 返回 0。均无任何告警通道。
- **最小修复**：接入说明明确规定日历窗口 ≥ `cooldown_days+1` 个交易日且必须含今日，缺今日/日历为空时由调用方记 warning（模块纯函数，可加返回哨兵或在 GateDecision.reasons 里提示"日历不足，冷却未校验"）；干跑脚本日历覆盖全窗口无此问题。

### S5. `clamp_buy_qty` 缺北交所分支；全关实例对科创板零股加仓非零行为（实测复现）

- **最小修复**：模块补 bse 分支（与上游逐字一致）；`evaluate_entry` 对 `intended_qty` 不做二次 clamp（上游已保证合法手数，闸门职责是"只缩量"，重复取整引入了新的数量语义），或至少在接入说明写明该边界。
